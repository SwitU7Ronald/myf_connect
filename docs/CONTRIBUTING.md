# Engineering Contribution Governance

## The Uncompromising Git Workflow
Contribution to this enterprise ecosystem is governed by an absolute, deterministic Git workflow. The primary execution trunk is the sacred source of theoretical truth. All architectural modifications, state transformations, and structural evolutions must originate from strictly typed, mathematically isolated Git branches. Direct manipulation of the primary branch is an absolute violation of repository protocols. The integration of any abstraction or concrete logic is entirely gated behind an uncompromising Pull Request validation matrix.

## Structural Branch Nomenclature
The taxonomy of branches is mathematically governed to dictate the exact theoretical intent of an isolated workflow. 
*   Branches must utilize a rigid semantic prefix dictating the precise category of the architectural mutation.
*   The prefix must be followed by a deterministic string identifying the exact structural perimeter or isolated feature micro-frontend being addressed.
*   Ambiguous nomenclature, arbitrary naming structures, or deviation from the semantic standard will result in instantaneous branch rejection by automated Git validation hooks.

## The Semantic Anatomy of a Commit
A commit message within this repository serves as a permanent architectural log and must adhere to strict mathematical laws.
*   **The Semantic Prefix:** Every commit must announce the precise theoretical nature of the structural patch.
*   **The Deterministic Payload:** The commit body must mathematically articulate the exact "Why" and "How" of the paradigm shift. It must explicitly define the previous theoretical state, the rationale for the architectural evolution, and the specific consequence of the new implementation. Casual annotations are strictly prohibited.

## The Absolute Pull Request Validation Matrix
A Pull Request is a proposition to alter the global enterprise foundation. It will only achieve integration upon fulfilling an absolute checklist:
1.  **Clean Architecture Integrity:** The modification must not pollute the Domain core with external dependencies or violate the unidirectional flow of state.
2.  **Memory Governance:** The patch must be mathematically verified to ensure all streams and controllers are aggressively disposed of to prevent memory leaks.
3.  **Isolation Law Verification:** Cross-feature directory contamination is an automatic rejection vector. Local features must remain strictly encapsulated.
4.  **Absolute QA Doctrine:** The Pull Request must provide mathematical proof of complete isolated unit testing for the modified logic matrix.
5.  **Static Analysis Determinism:** The compiled codebase must flawlessly clear the automated Flutter linting and style guide matrix with zero warnings.
